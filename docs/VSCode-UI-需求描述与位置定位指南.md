# VS Code UI 需求描述与位置定位指南

本指南用于把“这里加个按钮”“树上右键加功能”这类口头需求，转成开发、测试和评审都能准确理解的描述。

## 一条完整需求的写法

建议按下面的顺序描述：

> 在【界面区域】的【目标对象】上，通过【交互入口】提供【命令名称】；仅当【显示条件】时显示。执行后【预期结果】。

例如：

> 在 **Project Atlas 视图**的**项目节点**上，通过**节点右键菜单（View Item Context Menu）**提供“删除项目”命令；仅对本地项目显示。执行后先要求用户确认，再从项目列表中移除记录，不删除磁盘目录。

为避免歧义，应至少说明：

- 界面区域：用户在 VS Code 的哪个位置操作。
- 目标对象：针对整个视图、空白处、某类树节点、文件、编辑器，还是某个页面。
- 交互入口：标题栏按钮、右键菜单、命令面板、快捷键等。
- 命令行为：命令做什么，以及成功、取消、失败时的结果。
- 显示条件：哪些状态、节点类型或上下文下显示/禁用。

## 常见界面位置术语

| 用户看到的位置                     | 推荐中文描述                         | 常用英文/API 术语                               | VS Code 菜单位置                         |
| ---------------------------------- | ------------------------------------ | ----------------------------------------------- | ---------------------------------------- |
| Tree View 标题右侧的一排按钮       | 视图标题栏操作                       | View Title Actions                              | `view/title`                             |
| 对树中的某一个节点右键             | 树节点右键菜单；视图项上下文菜单     | View Item Context Menu / Tree Item Context Menu | `view/item/context`                      |
| 鼠标悬停树节点时，其右侧出现的图标 | 树节点内联操作；列表项操作按钮       | Tree Item Inline Actions / Inline Actions       | `view/item/context`，`group: inline`     |
| 对 Tree View 空白区域右键          | 视图空白区域右键菜单；视图上下文菜单 | View Context Menu                               | 通常为 `view/item/context`，配合条件区分 |
| 左侧资源管理器中对文件或文件夹右键 | Explorer 文件/文件夹右键菜单         | Explorer Context Menu                           | `explorer/context`                       |
| 编辑器标签页区域右上角按钮         | 编辑器标题栏操作                     | Editor Title Actions                            | `editor/title`                           |
| 在文本编辑区右键                   | 编辑器上下文菜单                     | Editor Context Menu                             | `editor/context`                         |
| `Cmd/Ctrl+Shift+P` 打开的列表      | 命令面板命令                         | Command Palette Command                         | `commandPalette`                         |
| 左侧最外层的图标列                 | 活动栏                               | Activity Bar                                    | `activitybar`                            |
| 点击活动栏图标后显示的侧边栏分组   | 视图容器                             | View Container                                  | `viewsContainers`                        |
| 视图内的树形列表                   | 树视图                               | Tree View                                       | `views`                                  |
| 状态栏左右两侧的项目               | 状态栏项目                           | Status Bar Item                                 | `statusBar/left` 或 `statusBar/right`    |
| 顶部菜单栏中的菜单                 | 菜单栏命令                           | Menu Bar Command                                | 例如 `commandPalette`、`editor/title` 等 |

## 树视图需求的精确定位

树视图最容易混淆“整个视图”和“某一个节点”。描述时请明确对象：

| 目标对象       | 推荐说法                                  | 示例                                    |
| -------------- | ----------------------------------------- | --------------------------------------- |
| 整个视图       | 在 Project Atlas 视图中                   | 在 Project Atlas 视图标题栏添加“刷新”。 |
| 视图标题       | 在 Project Atlas 视图的标题栏中           | 在标题栏操作中添加“新建项目”。          |
| 空白区域       | 在 Project Atlas 视图的空白区域右键菜单中 | 空白区域右键可“导入项目”。              |
| 某类节点       | 在项目节点的右键菜单中                    | 项目节点右键可“重命名”。                |
| 子节点         | 在仓库节点的右键菜单中                    | 仓库节点右键可“在终端打开”。            |
| 特定状态的节点 | 在收藏项目节点的右键菜单中                | 仅收藏项目显示“取消收藏”。              |

不要只说“tree 上加一个 action”。更好的说法是：

> 在 **Project Atlas Tree View** 的**项目节点**右键菜单中新增“复制项目路径”，并仅在节点包含本地路径时显示。

## 节点右键菜单与右侧内联操作

两者都可以针对同一个树节点，也都通常注册在 `view/item/context`；区别在于用户看到和触发它们的方式。需求中必须明确写“右键菜单”或“内联操作”，不要只写“节点 action”。

| 类型         | 用户如何看到                             | 推荐中文名称                   | 英文/API 术语                             | 实现标记                               |
| ------------ | ---------------------------------------- | ------------------------------ | ----------------------------------------- | -------------------------------------- |
| 节点右键菜单 | 对节点点击鼠标右键后，在弹出菜单中选择   | 树节点右键菜单                 | View Item Context Menu                    | 默认菜单分组，例如 `group: navigation` |
| 节点右侧图标 | 鼠标悬停在节点上时，节点右侧显示图标按钮 | 树节点内联操作；列表项操作按钮 | Tree Item Inline Actions / Inline Actions | `group: inline`                        |

示意：

```text
项目 A                                      [编辑] [删除]  ← 节点右侧内联操作

项目 A（鼠标右键）
├─ 打开项目
├─ 编辑项目                                             ← 节点右键菜单
└─ 删除项目
```

选择原则：

- **节点右键菜单**：适合次要、较少使用、需要较长文字说明或存在风险的操作，例如“删除项目”“导出配置”。
- **节点右侧内联操作**：适合高频、可快速理解、图标语义清晰的操作，例如“刷新”“编辑”“复制”。
- 同一命令可以同时出现在两处；需求中应明确写“同时保留右键菜单入口”。

正确示例：

> 在项目节点的**右侧内联操作（Tree Item Inline Action）**中新增“编辑项目”图标；鼠标悬停节点时显示。同时在该项目节点的**右键菜单**中保留“编辑项目”文字菜单项。

> 在项目节点的**右键菜单**中新增“删除项目”；不要将其作为右侧内联操作展示。执行前必须二次确认。

## 需求模板

### 新增命令

> 在【视图/页面】的【标题栏操作 / 节点右键菜单 / 节点右侧内联操作 / 空白区域右键菜单 / 命令面板】中新增“【命令名称】”。目标对象为【对象类型】；当【条件】时显示。执行后【结果】。

### 调整现有命令位置

> 将“【命令名称】”从【原位置】移动到【新位置】。该命令应作用于【目标对象】，并在【条件】下显示。

### 修改显示逻辑

> “【命令名称】”位于【位置】；仅当【节点类型/状态/配置条件】时显示，其他情况下【隐藏/禁用】。

### 有风险的操作

> 在【目标对象】的右键菜单中提供“【命令名称】”。执行前显示确认提示，明确说明【影响范围】；确认后【结果】。该操作【是否删除磁盘文件、是否可恢复】。

## 可直接复制的示例

> 在 Project Atlas 视图的**视图标题栏操作（View Title Actions）**中新增“刷新项目列表”。该命令作用于整个视图，无需选中节点；执行后重新读取本地项目配置并刷新树。

> 在 Project Atlas 视图的**项目节点右键菜单（View Item Context Menu）**中新增“在资源管理器中显示”。仅对具有本地目录的项目显示；执行后在系统文件管理器中定位该项目目录。

> 在 Project Atlas 视图的**项目节点右侧内联操作（Tree Item Inline Action）**中新增“编辑项目”图标。鼠标悬停项目节点时显示；同时保留右键菜单中的“编辑项目”文字菜单项。

> 将“删除项目”从**视图标题栏操作**移至**项目节点右键菜单**。命令只作用于当前右键选中的项目，执行前需确认；确认后仅删除项目记录，不删除本地文件。

> 在 Project Atlas 视图的**空白区域右键菜单**中新增“导入项目”。不要在项目节点右键菜单中显示，避免用户误以为导入操作会影响该项目。

> 为“复制仓库地址”增加**命令面板入口（Command Palette Command）**，同时保留仓库节点右键菜单入口；从命令面板执行时，如果未选中仓库则提示用户选择目标仓库。

## 提交需求前的检查清单

- 是否写清楚了具体视图或页面名称？
- 是否区分了标题栏、空白区域、节点右键菜单和节点右侧内联操作？
- 是否说明命令作用于哪一类节点？
- 是否定义了显示、隐藏或禁用条件？
- 是否说明执行后的可见结果与错误提示？
- 涉及删除、覆盖、同步时，是否写清楚影响范围和确认方式？
- 一个命令有多个入口时，是否逐一列出？

## 推荐术语速查

优先使用“命令（Command）”描述可执行功能，“操作入口（Action / Entry Point）”描述按钮或菜单项，“上下文菜单（Context Menu）”描述右键菜单，“内联操作（Inline Action）”描述节点右侧的图标按钮，“节点（Tree Item）”描述树中的单项。

如果不确定实现位置，可以先用用户语言加括号说明，例如“项目树顶部右侧的标题栏按钮（View Title Actions）”。这比只写“上面的 action”更容易被准确实现。
